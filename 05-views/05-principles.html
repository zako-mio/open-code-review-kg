12 Factor Agent 原则 · 12 条

原则主张OCR 对应机制审查结论
ag-nl2tool自然语言→工具调用LLM 将自然语言转换为结构化工具调用对象受限 6 工具 ReAct 循环：模型输出结构化工具调用（file_read/file_find/code_search/file_read_diff/code_comment/task_done）合规
ag-prompts掌控你的 Prompt像管理代码一样版本化、测试、部署 prompt场景化提示词模板（internal/config/template/prompts/）随仓库版本化，图谱资产化（assets/prompts/），plan/main/filter 相位分离合规
ag-context掌控上下文窗口对上下文进行工程化管理（上下文工程）三区压缩（frozen/compress/active 60%/80% 阈值）+ 预算前瞻（estimate.go）+ filterLargeDiffs 80% 丢弃 + prompt-cache 亲和键合规
ag-tools工具即结构化输出工具只是模型的结构化输出，可无限组合tools.json 定义 schema，工具注册表 Registry + MCP 动态工具扩展（ToToolDef 统一转换）合规
ag-state统一执行/业务状态将执行状态与业务状态统一为单一事实源Run Manifest（ocr.run-manifest/v1）作为覆盖度单一事实源 + JSONL 会话作为执行轨迹事实源合规
ag-pause启动/暂停/恢复用简单 API 管理 Agent 生命周期ocr review --resume <session-id> / ocr scan --resume：指纹复用跳过已完成，未决项重跑合规
ag-human工具调用联系人类把人类接入作为一类工具调用，主动寻求批准--audience human|agent 双受众输出 + CI 评论回贴（GitHub/GitLab discussion）将审查结论送到人类面前部分合规
ag-control掌控控制流控制流由代码决定，LLM 只做决策点确定性流水线（8 步时序）+ 规则引导分派（四层规则链）决定控制流，LLM 只在『看 diff 出评论』决策点工作合规
ag-errors压缩错误进上下文把错误摘要压缩回上下文窗口供模型反思q-retry 错误分类（ErrorClass × FailurePhase）+ retry_report 压缩重试明细；LLM 调用失败结构化入报告而非原始堆栈合规
ag-small小而专注的 Agent用多个小 Agent 而非一个巨型 Agent 解决问题文件级子 Agent：每文件独立 Plan+ReAct+反思，8 并发，上下文隔离——多个小 Agent 而非一个巨型 Agent合规
ag-trigger随处触发从任何触发源唤起 Agent，触达用户所在之处GitHub PR 事件/评论触发、GitLab MR、Gerrit、斜杠命令（Claude Code）、skill（Codex/Cursor/OpenCode）、VSCode 面板合规
ag-reducer无状态 Reducer将 Agent 建模为无状态 reducer（state, event）→ statereviewItemFingerprint=sha256(mode+old+new+diffText) + manifest 状态机：同输入同指纹同结果，事件流可重放（JSONL 回放）合规

审查小结

OCR 的核心架构（确定性流水线 + 规则引导分派 + 文件级子 Agent + 独立反思）与 12 Factor Agent 高度同构：控制流由代码决定（ag-control）、上下文工程化（ag-context）、小 Agent 组合（ag-small）、无状态可重放（ag-reducer）均是完全合规。与 12 Factor App 的对照同样出色：配置外置（app-config）、后端服务可替换（app-backing）、日志事件流（app-logs）、可处置性（app-disposability）全部落在原则坐标系上。

两处张力/部分合规：①开发/线上等价——CI 与本地环境差异由配置优先级弥合而非环境等价；②人类接入——审查工具面向人类审查员但无主动 seek-approval 流程，属审查场景的合理取舍（审查非执行类任务）。
