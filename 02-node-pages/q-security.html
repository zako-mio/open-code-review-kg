What · 是什么

路径穿越防护（WithinBase+EvalSymlinks）、git grep 拒 '..'、viewer hostGuard 防 DNS-rebind、manifest 哈希不含密钥
FileReader 路径穿越防护：所有文件读取经 pathutil.WithinBase + EvalSymlinks 双重校验，符号链接与 ../ 均无法逃逸仓库根目录
file_read 工具调用设 500 行上限，防止模型读取超长文件造成上下文爆炸与滥用
git grep 操作拒绝 '..' 路径穿越，并拒绝以 '-' 开头的 ref（防选项注入攻击）
viewer 模块的 hostGuard 防 DNS-rebind：读取含源码的 JSONL 时校验 Host 头，避免恶意站点通过 DNS 重绑定窃取本地审查数据
manifest 哈希计算不包含密钥字段，规则清单的完整性校验不会把敏感凭据带入哈希或日志
规则文件采用相对路径解析并防目录穿越，项目规则无法通过构造路径读取仓库外文件
代码本地处理：审查数据不强制上传，隐私可控，适用于涉密代码库

Why · 为什么

原理 · Principle

CLI 工具运行在开发者机器上且会读取仓库文件，路径穿越/符号链接是本地工具被利用的经典入口，必须从源头拦截

模型可能被提示注入诱导读取任意文件，500 行上限与路径白名单是纵深防御的关键一环

DNS-rebind 攻击可让恶意网页读取 localhost 服务数据，viewer 读取含源码 JSONL 时必须防 Host 头伪造

安全设计直接决定该工具能否被用于涉密或私有代码库——本地处理是合规底线

How · 怎么做

路径安全默认内置：无需配置，所有 FileReader 调用自动执行 WithinBase + EvalSymlinks 双重校验，任何逃逸尝试直接拒绝
限制读取规模：模型请求超过 500 行的文件时自动截断，大文件走分片/摘要路径而非全量注入
安全使用 git 相关功能：ref 名称以 '-' 开头或含 '..' 时被拒，避免 --flag 注入与目录穿越
启用 viewer 前确认 hostGuard 生效：验证非授权 Host 头的请求被拒绝，再开放本地端口供浏览器访问
核对 manifest 哈希：校验规则文件完整性时确认哈希计算只覆盖文件内容，不包含其中可能的密钥字段
自定义规则文件使用仓库内相对路径，且解析时受目录穿越防护约束，不要用绝对路径引用仓库外文件

案例 · Cases

代表性案例
审查含敏感业务的私有仓库：数据全程本地处理，无需上传，符合数据隐私要求
恶意仓库防御：打开不受信来源的 PR 分支时，路径穿越与 git grep 注入防护确保模型只能看到仓库内内容
浏览器查看审查结果：viewer 的 hostGuard 拦截 DNS-rebind，恶意网页无法读取本地审查 JSONL
CI 中运行：受控环境 + 路径白名单，即使代码来自外部贡献者也不会逃逸工作目录

反模式 · Anti-patterns

  • 用绝对路径或 '../' 形式在自定义规则中引用外部文件，绕过相对路径约束，破坏目录穿越防护
  • 为提升审查深度盲目调高 file_read 上限或禁用截断，把模型暴露给超大文件并放大注入面
  • 对不受信仓库关闭 hostGuard 或开放 viewer 到 0.0.0.0，使 DNS-rebind 攻击面重新打开
  • 在规则文件或配置文件里明文存放 API 密钥，虽哈希不计入，但文件本身仍可能被误提交或泄漏
